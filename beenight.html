ORIGIN STORY // HOUSEWARMING PARTY → PUBLIC SAAS

Why Existing Trivia Apps Fell Short

When my wife and I moved into our new apartment together, we decided to host an interactive spelling bee for our housewarming party. Existing party trivia tools were designed around multiple-choice phone quizzes rather than live verbal stage performance—where an emcee judges spoken spelling in real time while a living-room TV drives crowd engagement. After the housewarming party became a hit with our friends, I re-architected BeeNight from a single-household LAN build into a public, multi-room SaaS platform with 5 live-switchable broadcast themes, platform-locked branding (PLATFORM_BRANDING separated from mutable GameConfig), and progressive disclosure separating essential setup (Rules & Theme) from power-user modifiers (Advanced Features).

02 // System Architecture

Local-First Isomorphic Reducer & Dual-Transport Relay

Zero-DB Multi-Tenant SaaS

To transition BeeNight from a private housewarming prototype into a public multi-tenant SaaS without paying for database hosting or storing personally identifiable guest photos on a server, all game rules live in a single zero-dependency TypeScript engine (src/domain/gameEngine.ts) shared isomorphically between the React client and the stateless Node.js Socket.IO relay.

Admin (/admin) + TV (/tv)

HIGHLIGHT 01 // src/domain/gameEngine.ts

Isomorphic Config Whitelisting & Schema Self-Healing

Because BeeNight hydrates state from browser localStorage, imported JSON backup files, and untrusted WebSocket payloads, schema drift or legacy keys could corrupt runtime state or overwrite platform-owned branding. Using DEFAULT_GAME_CONFIG as the single runtime source of truth eliminates manual validation boilerplate while guaranteeing that deprecated or unauthorized fields (such as legacy eventTitle / eventSubtitle) are stripped during both hydration (normalizeHydratedGameState) and live admin:updateConfig events.

src/domain/gameEngine.ts — Runtime Config Guard 
const ALLOWED_CONFIG_KEYS = new Set<string>(
  Object.keys(DEFAULT_GAME_CONFIG)
);

// Whitelists untrusted config patches down to DEFAULT_GAME_CONFIG keys.
// Drops retired branding keys from backups or relayed socket events.
export function pickKnownConfigKeys(patch: unknown): Partial<GameConfig> {
  if (!patch || typeof patch !== 'object') return {};
  return Object.fromEntries(
    Object.entries(patch as Record<string, unknown>).filter(([key]) =>
      ALLOWED_CONFIG_KEYS.has(key)
    )
  ) as Partial<GameConfig>;
}
HIGHLIGHT 02 // src/utils/crypto.ts

Pure-TypeScript FIPS 180-4 SHA-256 & QR Capability Pairing

When a Host scans the TV's QR code over a local Wi-Fi network (http://192.168.x.x:5173), browsers treat non-HTTPS LAN origins as insecure contexts and disable window.crypto.subtle. I implemented a zero-dependency FIPS 180-4 SHA-256 engine in pure TypeScript. Each session generates a memorable passphrase (e.g., HONEY-CROWN-42), stores only passphraseSalt and passphraseHash, and embeds the capability hash in the QR URL (?room=BEE-XXXX&auth=<hash>) for instant one-scan authentication.

src/utils/crypto.ts — Pure-TS SHA-256 & Salted Verify 
for (let i = 0; i < 64; i++) {
  const S1 = rightRotate(e, 6) ^ rightRotate(e, 11) ^ rightRotate(e, 25);
  const ch = (e & f) ^ (~e & g);
  const temp1 = (h + S1 + ch + SHA256_K[i] + w[i]) >>> 0;
  const S0 = rightRotate(a, 2) ^ rightRotate(a, 13) ^ rightRotate(a, 22);
  const maj = (a & b) ^ (a & c) ^ (b & c);
  const temp2 = (S0 + maj) >>> 0;
  h = g; g = f; f = e; e = (d + temp1) >>> 0;
  d = c; c = b; b = a; a = (temp1 + temp2) >>> 0;
}

export function hashPassphrase(passphrase: string, salt: string): string {
  const normalized = normalizePassphrase(passphrase);
  return normalized ? sha256Hex(`beenight:v1:${salt}:${normalized}`) : '';
}
HIGHLIGHT 03 // src/components/ParticipantAvatar.tsx

Non-Destructive Face Focal Framing for Contestant Avatars

Party guests submit portraits in wildly different aspect ratios (vertical selfies, group shots, off-center crops). Re-encoding images on every pan/zoom adjustment would degrade JPEG quality and bloat localStorage. Instead, ParticipantAvatar.tsx pairs a single 256×256 compressed JPEG data URL with three focal coordinates (photoFocusX, photoFocusY, photoScale). Binding both objectPosition and transformOrigin to the same percentage coordinates scales directly around the contestant's face across circular badges and 16:9 TV spotlight cards.

src/components/ParticipantAvatar.tsx — Focal Framing 
const clampedFocusX = Math.max(0, Math.min(100, Number(photoFocusX) || 50));
const clampedFocusY = Math.max(0, Math.min(100, Number(photoFocusY) || 50));
const clampedScale = Math.max(1, Math.min(2.5, Number(photoScale) || 1));

<img
  src={resolvedPhotoUrl}
  alt={name}
  className="w-full h-full object-cover transition-transform duration-150"
  style={{
    objectPosition: `${clampedFocusX}% ${clampedFocusY}%`,
    transform: clampedScale > 1 ? `scale(${clampedScale})` : undefined,
    transformOrigin: `${clampedFocusX}% ${clampedFocusY}%`,
  }}
/>
HIGHLIGHT 04 // src/utils/audio.ts

Procedural Web Audio API Game-Show Synthesizer

To give the living-room TV broadcast authentic game-show feedback with zero external MP3/WAV assets or network preloading delays, audio.ts synthesizes all sound effects (correct chimes, wrong buzzers, countdown ticks, drumrolls, and podium fanfare) procedurally in real time. Layering a fundamental triangle wave with an octave-doubled sine harmonic (freq * 2) and shaping the envelope via exponentialRampToValueAtTime produces a warm, click-free C5→C6 major 7th chime while passive pointerdown / keydown listeners automatically unlock suspended browser AudioContext instances.

src/utils/audio.ts — Dual-Oscillator Victory Chime 
// C5 -> E5 -> G5 -> B5 -> C6 sparkly major 7th chime
const notes = [523.25, 659.25, 783.99, 987.77, 1046.5];
notes.forEach((freq, idx) => {
  const osc = ctx.createOscillator();
  const subOsc = ctx.createOscillator();
  const gain = ctx.createGain();
  osc.type = 'triangle'; subOsc.type = 'sine';
  osc.frequency.setValueAtTime(freq, now + idx * 0.075);
  subOsc.frequency.setValueAtTime(freq * 2, now + idx * 0.075);
  gain.gain.exponentialRampToValueAtTime(0.24, startTime + 0.02);
  gain.gain.exponentialRampToValueAtTime(0.0001, startTime + duration);
});
04 // Architectural Challenges & Outcomes

Hard Problems Solved in the SaaS Migration

01

Migrating from Single-Instance Disk Persistence to Multi-Tenant Public SaaS

The Problem: The initial housewarming party build persisted state to a single data/gameState.json file and /uploads folder on the Node.js server. Launching that architecture publicly would cause every concurrent party to overwrite the same game state and expose personal guest photos across tenants.
The Solution: Extracted the reducer into a pure isomorphic engine (src/domain/gameEngine.ts), moved durable persistence to the organizer's browser via src/services/localStorageRepo.ts, and refactored server/stateStore.ts into a stateless, room-scoped (room:BEE-XXXX) in-memory relay with automatic state:push re-hydration if the relay server restarts mid-party.

02

Fitting High-Resolution Guest Photos Inside Browser localStorage Quotas

The Problem: Browser localStorage enforces a strict ~5MB origin limit. Uploading raw smartphone photos (3–8MB each) for 20+ party contestants immediately throws a QuotaExceededError.
The Solution: Built an HTML5 Canvas image compression pipeline (src/utils/imageCompressor.ts) that center-crops and downscales uploaded portraits client-side into 256×256 JPEG data URLs (quality: 0.82), reducing each photo from ~5MB to ~15–25KB (>99% reduction). Even a 50-contestant roster with custom photos and a 25-action undo stack consumes less than 1.5MB of localStorage.

03

Preventing Host Cognitive Overload During Live Stage Transitions

The Problem: During a fast-paced party, showing lobby presentation controls, word teleprompter cards, and round-reset buttons simultaneously on a small phone screen made it easy for the emcee to tap the wrong control.
The Solution: Redesigned HostView.tsx around strict stage-contextual component projection (LobbyPresentationCard, active turn teleprompter, HostLeaderboardCard, and HostPodiumCard) and decluttered TvView.tsx by removing persistent footers on Lobby, Ranks, and Podium views.
